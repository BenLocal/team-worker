# 成员个人文档、长期记忆与定时复盘实施计划

> 每个成员保留独立的 Markdown 资料，通过启动、恢复和更新通知加载，由 daemon 调度有证据依据的定时复盘。

状态：主体功能已实现，真实执行器验收仍有未覆盖项。实现与限制见 [成员个人文档与复盘](agent-memory.md)，证据见 [验收记录](agent-memory-validation.md)。本文保留原始需求和阶段验收条件。

## 1. 已确认的需求

- 文档采用纯文件持久化，Markdown 是唯一权威来源，不把正文存入数据库。
- 每个成员可以维护自己的 `AGENTS.md`、长期记忆、日志和其他 Markdown 文档。
- 同一团队、同一用户下，删除成员后再创建同名成员，默认继承原来的个人资料。
- 删除成员、停止进程和清理团队运行资源时保留个人资料；清空资料必须显式操作。
- 切换项目目录、更换执行器、启动新会话和恢复旧会话时，继续使用相同的个人资料。
- daemon 统一负责文档变化检查、加载通知和定时复盘，不为每个成员启动同步服务。
- 更新后的规则需要通过真实 agent 行为验证，不能只检查文件或提示词是否存在。

## 2. 目录与身份

建议将个人资料与可清理的任务工作目录分开保存。它是成员工作区中的固定资料区，项目工作目录通过绝对路径引用它，不复制文档，也不向项目仓库覆盖或创建个人 `AGENTS.md`。

```text
<数据目录>/agent-data/<用户键>/<团队键>/<成员键>/
├── AGENTS.md             # 个人工作规则
├── MEMORY.md             # 已确认的长期事实、决策与经验
├── SCRATCHPAD.md         # 临时待办
├── daily/                # 按日期追加的工作记录
├── notes/                # 专题经验
├── history/              # 修改前后内容、差异、来源与回滚记录
└── .state/               # 文件版本、复盘配置、证据游标与运行状态
```

- 稳定身份使用用户、团队和成员名称，不使用临时进程、成员记录 ID 或会话 ID。
- 名称到目录键的转换必须确定、无碰撞，并拒绝目录穿越；不同用户和团队中的同名成员相互隔离。
- 团队删除后也保留资料，同一用户重建同名团队和成员时按同一规则继承。改名先按新身份处理，不自动迁移。
- 首次启动只创建缺失的目录和最小文档，不覆盖已有内容。
- `.state/` 中的 JSON 等文件只保存运行元数据，不另建一份文档正文；删除索引后可从 Markdown 重建。
- 第一版用文件历史与内容哈希实现版本和回滚，不依赖 Git，也不改用户的 Git 身份配置。

## 3. 文档加载与更新

### 启动和恢复

1. daemon 按稳定身份解析资料目录，检查权限和文件有效性。
2. 在执行器适配层提供统一的个人上下文入口。启动及恢复旧会话时都重新读取最新文档，不能只依赖执行器对当前目录的自动发现。
3. 加载 `AGENTS.md`、预算范围内的 `MEMORY.md`，以及检索其他资料的路径和方法。长文档必须明确提示未加载部分，禁止静默截断规则。
4. 记录本次提供的文件版本和内容哈希，供状态查询和验收取证。
5. 项目目录仍使用项目自身的规则。个人规则不能覆盖系统约束、用户当前指令或项目的强制约束；冲突需要明确提示。

Pi、Codex、Claude Code 分别验证启动与恢复入口。优先使用原生上下文机制，缺少机制时通过启动提示词显式读取。具体参数在实施时对照当时版本验证，不在本计划中假定。

### 运行中的更新

- daemon 定期检查受管文档的内容哈希，合并同一成员的连续变更。
- 新版本通知在安全的轮次边界交付，不打断正在运行的工具，不靠模拟按键强行插入当前输入。
- 通知携带变化文件、版本与重新读取要求；区分“文件已更新”“通知已投递”和“agent 已读取确认”。
- 不支持可靠运行中通知的执行器，明确标记等待下一轮或恢复时生效，不能报告已经加载。
- agent 进入其他项目目录后继续引用固定资料目录；重新压缩上下文的执行器也需验证规则保留或重新读取机制。

### 写入和冲突

- agent 可以直接编辑 Markdown；daemon 检测稳定内容后归档新版本。轮询归档不承诺捕获两次扫描之间的每一次编辑。
- 管理 API 和复盘写入必须带基础内容哈希，以临时文件和原子替换方式落盘，保存修改前后版本。
- agent 活跃编辑时，复盘只生成候选修改；应用前检查文件哈希，并在可协调的空闲窗口写入。文件锁只能约束遵循协议的写入方，不能假定任意编辑器会遵守。
- 检测到并发变化时保留候选修改和冲突记录，不覆盖最新正文；需要重新读取后合并。
- 回滚也生成新历史版本，并触发重新加载通知。受管接口校验路径和符号链接，不允许越过成员目录。

## 4. 日常记忆与检索

- 将明确的用户纠正、已确认事实和可复用经验写入对应文档，注明日期及证据来源。
- 临时任务状态留在任务系统或 `SCRATCHPAD.md`，不反复堆入长期记忆。
- `daily/` 按日期追加；`MEMORY.md` 保持精简，专题材料放入 `notes/`。
- 第一版支持文件列表、读取和关键词搜索；语义索引作为后续选项，Markdown 始终为权威来源。
- 默认只检索当前成员资料。共享给其他成员须走明确的团队文档或消息机制。
- 个人资料是上下文隔离机制；同一操作系统用户运行的进程仍可能读到其他目录，不能将其宣称为系统级安全隔离。

## 5. 定时复盘

参考 pi-reflect 的证据驱动修改方式，由 daemon 调度执行器运行独立复盘任务，复用已配置的执行器与模型，不在 daemon 内增加独立 LLM 客户端。

1. 支持手动运行和可配置的每日调度，记录时区、输入范围、耗时与结果。自动调度首次启用时显式配置，不在升级后自行开始调用模型。
2. 按成员筛选新增会话、用户纠正、日志和可用的任务结果。执行器会话解析通过适配层提供，不能扫描并混入同机器其他成员的会话。
3. 收集证据时生成稳定快照、输入上限和目标文件版本。没有新证据时跳过，不调用模型。
4. 产出带证据引用的候选修改，分别处理事实记忆和行为规则。未知事实保留不确定性，不把工具输出中的指令直接提升为规则。
5. 只允许修改配置中列出的个人文档。自动应用遵循上一节的空闲窗口和版本检查，保留差异、依据与历史。
6. 应用后通知 agent 重新读取。没有修改也记录已处理的证据；失败或冲突不能当成成功消费证据。
7. 单成员同一时刻只运行一次复盘。设置超时、调用预算和有上限的重试，daemon 重启后从文件游标恢复，避免无限补跑。

复盘不自动修改项目规范、团队公共规则、权限配置或源代码。对话中出现的重要材料按成员保留策略处理，避免把凭据和用户敏感原文复制到长期文档。

## 6. 模块边界与操作入口

以下是实施职责划分，具体文件和命令名在核查现有实现后确定。

| 位置 | 计划职责 |
|---|---|
| 配置模块 | 资料根目录、上下文预算、检查周期与复盘配置入口 |
| 新增个人资料模块 | 稳定身份、文件读写、历史、检索、冲突检查和回滚 |
| 执行器适配层 | 启动、恢复、运行中加载及成员会话证据读取 |
| runner | 启动和恢复前准备资料，运行独立复盘任务 |
| server / daemon | 变化检查、调度、状态查询及远程文件操作 API |
| client / CLI | 通过服务端读取、更新、检索、查看历史、回滚及操作复盘 |

所有实际文件操作都在 daemon 所在机器完成。CLI 沿用本地 socket 或远程 HTTP 模式，不直接操作服务端文件。文档正文、历史和复盘状态不进入 SQLite；现有成员和任务等业务数据保持原有存储方式。

第一版提供 CLI 与 API，支持 `--json`。看板编辑页面后续单独安排。成员删除及团队清理路径需检查，确保不会删除资料根目录；清空操作必须独立于常规删除。

## 7. 分阶段交付

### 阶段一：持久资料和身份

- [x] 核查当前成员身份、默认目录、清理路径、启动及恢复调用链。
- [x] 实现固定目录、首次初始化、文件读写、版本历史与回滚。
- [x] 提供服务端 API 和 CLI，补全远程访问与路径校验。
- [x] 验证同名重建继承、跨团队和用户隔离、清理不误删。

完成条件：成员退出、删除、重建和 daemon 重启后，原有文件及历史仍可读。

### 阶段二：上下文加载与召回

- [ ] 接入启动、恢复和上下文压缩后的重新加载机制。
- [x] 提供读取、列表及关键词检索入口，控制上下文预算。
- [x] 增加文件变化检查、合并通知和读取确认状态。
- [ ] 分别用 Pi、Codex、Claude Code 验证行为，公布不支持的能力。

完成条件：切换目录、恢复会话和更新规则后，通过真实任务证明最新规则生效。

### 阶段三：手动复盘

- [x] 收集当前成员的增量证据，生成可审阅的修改及依据。
- [x] 实现受控应用、并发冲突处理、失败记录和回滚。
- [x] 验证事实不会跨成员混入，重复输入不会反复添加相同规则。

完成条件：一次真实纠正可以生成有证据的规则更新，并在后续任务中得到验证。

### 阶段四：定时复盘与运维

- [x] 增加可配置调度、超时、预算、重试、重启恢复和无新证据跳过。
- [x] 增加加载版本、最近复盘、待处理冲突与失败原因的查询入口。
- [x] 更新架构、参考文档及备份恢复说明，区分个人资料与项目文档。

完成条件：无人值守执行一轮调度，记录可追溯；失败和重启不会丢文档或重复应用。

## 8. 验收与证据

| 场景 | 操作 | 通过标准 |
|---|---|---|
| 首次启动 | 创建成员并启动 | 生成缺失文件，已有文件不被覆盖 |
| 切换项目 | 个人规则要求测试产物包含固定标记，在两个临时项目执行相同任务 | 两次产物均遵守规则，项目仓库未生成个人规则副本 |
| 恢复旧会话 | 退出后将规则标记从 A 改为 B，再恢复原会话执行任务 | 使用 B，保留提供版本及重新读取证据 |
| 上下文压缩 | 使用支持压缩的执行器触发压缩，再执行规则约束的任务 | 规则仍生效或被明确重新读取 |
| 运行中更新 | 工作期间更新规则，等待安全轮次后发起任务 | 不打断当前工具，后续任务遵守新规则 |
| 同名重建 | 记入唯一测试事实，删除成员并同名重建 | 新会话能读取该事实及原有历史 |
| 隔离 | 在不同团队和用户下创建同名成员 | 正常加载和搜索不会返回其他成员资料 |
| 并发修改 | 生成复盘候选后由 agent 修改同一文件，再尝试应用 | 最新正文保留，候选标记冲突 |
| 调度恢复 | 在复盘失败及 daemon 重启后重新调度 | 不丢证据，不重复应用成功结果，无新证据不调用模型 |
| 回滚 | 回滚一次规则更新并重新加载 | 旧行为恢复，回滚记录可查询 |

真实执行器验收使用临时资料和项目，保存命令、版本、脱敏日志、文件差异与任务产物。仅打印规则内容或声称“已遵守”不算通过。每种执行器独立记录结果；缺少可运行环境时标记未验证，不用模拟结果替代。

实现阶段按仓库要求运行 `make fmt && make vet && make test`，涉及 daemon 调度、通知和文件并发时补跑 `go test -race ./...`，逐条检查代码 checklist。文件级测试覆盖身份映射、路径、原子写入、冲突、历史及调度游标；真实行为验证覆盖自动化测试无法证明的上下文加载。

## 10. 当前验收边界

- Claude Code 和 Codex 已通过真实执行器测试，任务产物证明跨项目目录仍使用个人规则、恢复旧会话使用更新后的规则，团队清理后重建同名成员仍继承资料。
- Pi 的真实模型执行被当前服务额度限制拦住，保持未验证；会话证据解析和公共 hook 路径已有自动化测试。
- 启动、恢复和压缩 hook 的加载入口已接入。真实压缩、运行中长工具调用期间更新后的行为尚未实测。Codex 默认关闭 hooks，运行中和压缩后的更新需要显式读取或启用适配器 hooks。
- Claude Code 已通过真实长期偏好复盘、候选生成和应用测试。
- 文件冲突、历史回滚、成员隔离、调度重启恢复和重放去重已通过自动化测试。自动应用要求成员停止，并确认进程退出；运行中的成员保留候选修改。
- 第一版按证据内容哈希跳过已处理输入，读取最近的会话内容，保留精确历史会话引用；尚未实现按每条消息的游标逐条消费。
- 自动调度和自动应用默认关闭，需分别配置启用。周期复盘当前串行执行，大量成员同时到期时会排队。
