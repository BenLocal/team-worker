复现命令：


Claude Code 的真实复盘另用 `--reflection-only` 验证。将“后续报告的时间戳使用 ISO 8601 与 UTC”作为测试用的长期偏好写进每日记录，由独立批处理生成候选，应用后 `MEMORY.md` 包含 UTC 偏好，检查通过。

```bash

```

第一次复盘实测使用临时项目的发布通道事实，模型返回合法的空候选。随后将材料改为明确的长期偏好，并在复盘提示中分别说明事实记忆与行为规则的目标，测试通过。空候选仍是合法结果，系统不会为了生成修改而强制添加规则。

真实压缩后的行为、运行中的长工具调用期间更新规则后的行为，以及 Pi 的模型执行仍未实测。公共钩子路径的自动化测试不能替代这些真实执行器结果。

## 自动化检查

要求的检查命令：

```bash
make fmt && make vet && make test
go test -race ./...
bash scripts/check-sensitive.sh
python3 -m py_compile scripts/verify-agent-memory.py
```

本轮上述检查全部通过，包括最终源码的全量 race 检查。

新增测试覆盖：

- 文件重新打开后仍保留，用户与团队之间的资料隔离。
- 版本过期写入被拒绝，回滚生成历史，直接编辑被归档。
- 拒绝目录穿越和符号链接，上下文超出预算时明确要求读取完整文件。
- 旧运行和旧文件哈希不能确认读取；操作者查看上下文不会消费成员待加载的更新。
- 恢复与轮次钩子读取新规则，未变化内容不反复注入。
- 被拒绝的 spawn 不改变当前成员的资料加载运行标识。
- 精确会话匹配，不读取其他成员的日志，不将工具结果混入证据。
- 任务结果按成员收集，多个用户下同名任务负责人有歧义时跳过。
- 复盘候选冲突保留原文，重复应用和重复证据不会重复修改。
- 每日重试有上限，daemon 重建后继续处理候选，无新证据不再调用模型。
- 进程实际存活时，即使数据库已经记录退出，也拒绝应用复盘修改。
- 批处理取消能结束运行，协调身份不传给复盘进程。
- Codex 的 `--no-daemon` 保留在根命令位置，兼容批处理与恢复。

自动调度测试使用本机子进程输出可控候选，验证调度和落盘；真实 Claude Code 复盘测试验证模型能够生成并应用偏好修改。这两类证据分别说明不同能力。
