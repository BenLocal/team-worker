# Magpie 网关兼容问题

> Claude Code 经 Magpie 转发到各家 Anthropic 兼容接口时踩过的格式坑，以及排查方法。

- 2026-11-06：`group/opencode-first`（opencode-go 优先、DashScope 后备）在 opencode-go 过载（429 `cell is at capacity` / `overloaded`）时退到 DashScope，Claude Code 大量报 `API Error: 400 DashScope: Request body format invalid`（部署主机近 4 小时 133 次 DashScope 请求 100 次 400）→ 原因：Magpie 给 Claude Code 写了 `ENABLE_TOOL_SEARCH=true`，会话用 ToolSearch 加载过延迟工具后，之后每个请求的历史里都有 role 为 `system` 的消息带 `{"type":"tool_addition","tool":{"type":"tool_reference",...}}` 块；Magpie 走 Anthropic 接口时原样转发，DashScope 不认这个块，整请求 400。实测：抓到的真实失败请求（约 796KB）只删 `tool_addition` 就 200，删 `context_management` / `thinking` / `output_config` / `metadata` 仍 400，role 为 system 的纯文本消息本身没问题。→ 做法：在 Magpie 的 `~/.config/magpie/settings.json` 加 `"modelAPIs": {"dashscope/<模型>": "chat"}`，让 DashScope 改走 OpenAI 兼容的 chat 接口（供应商要配了 chat 地址）；chat 路径的内部格式没有 `tool_addition`，自动丢掉。改完同一最小复现流式、非流式都 200，Claude Code 真实工具调用正常，用量里 endpoint 显示 `/v1/messages → /v1/chat/completions`。v0.1.2925 没有 `magpie model api` 命令（新版才有），直接改 settings.json，网关每个请求都读，无需重启。settings.json 在 home 卷里，重建容器不丢；`team-worker-ops magpie` 不碰它。
- 2026-11-06：Magpie 对这类块的处理（来源：上游 issue #2042、#2338、#5404 维护者说明）：对 Kimi Code、opencode.ai 上的 DeepSeek、api.deepseek.com 预先去掉；其他供应商只有在报错里出现可识别字样（如 `unknown variant tool_addition`）时才学会去掉并重发。DashScope 只回笼统的 `Request body format invalid`，匹配不上，所以每次原样失败。新接入的 Anthropic 兼容供应商出现笼统 400 时，先怀疑这一点。
- 2026-11-06：排查方法：Magpie 不记录请求体。在容器里临时起一个只监听 127.0.0.1 的转发代理，失败时保存请求体；用 `claude -p ... --resume <会话> --fork-session --model <供应商/模型> --settings '{"env":{"ANTHROPIC_BASE_URL":"http://127.0.0.1:<代理端口>"}}'` 把一个长会话的完整历史重放过去（`~/.claude/settings.json` 的 env 会盖过命令行环境变量，必须用 `--settings`）。再对抓到的请求体逐项删减重发定位字段。分叉会话会在 `~/.claude/projects/<目录>/` 下留下新的 jsonl，查完按创建时间找出删掉，原会话不动。
- 2026-11-06：改走 chat 接口后，DashScope 请求的 `reasoning_tokens` 为 0，可能没有开思考（待验证：是否需要给 chat 路径传思考参数）；作为后备可接受。
